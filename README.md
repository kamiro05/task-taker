# FlowConnect Task Taker

Расширение Chrome (MV3) для `alpha.flowconnect-group.com`: мгновенно замечает новые заявки и первым нажимает «взять», соблюдая включённые типы задач и их приоритеты.

> ⚠️ Автоматизация может нарушать правила платформы. Риск для аккаунта принимает пользователь. Первое живое включение — только в режиме **Dry Run**.

## Установка

1. Открыть `chrome://extensions`
2. Включить «Режим разработчика»
3. «Загрузить распакованное расширение» → выбрать папку проекта
4. Требуется Chrome 111+ (используется `world: "MAIN"` в manifest)
5. **Перезагрузить открытые вкладки платформы** — Chrome не внедряет контент-скрипты
   в вкладки, открытые до установки/обновления расширения. Либо нажмите в попапе
   «Подключить движок к этой вкладке», находясь на странице задач.
6. Признак жизни: на вкладке `/tasks` в журнале появляется запись
   «движок загружен на странице задач».

## Если журнал пуст

1. Вкладка открыта до установки → перезагрузите её или нажмите кнопку
   «Подключить движок к этой вкладке» в попапе.
2. После обновления кода: `chrome://extensions` → ↻ (обновить расширение) → снова
   перезагрузить вкладку.
3. Ошибки JS попадают в тот же журнал (событие `error`).

## Первый запуск (безопасно)

1. Открыть попап расширения → включить **Dry Run** (включён по умолчанию), мастер-тумблер **Захват включён**
2. Открыть `/tasks`, дождаться новых заявок
3. Проверить журнал в попапе: какие типы распознаны, что было бы взято
4. В «Приоритетах типов» включить нужные (галочка) и расставить порядок ↑↓.
   Список предзаполнен наблюдёнными типами платформы — все выключены до вашего выбора;
   свои типы добавляйте полем ввода. Автоподбора из журнала больше нет — только ваш список.
5. Выключить Dry Run только когда журнал показывает корректную работу

## Как работает

- **Хук WebSocket + EventSource** (`src/injected/inject.js`, main world, `document_start`): перехватывает входящие кадры WS и SSE, извлекает `{id, type}` новой задачи и передаёт в content script раньше отрисовки.
- **MutationObserver** (`src/content/content.js`): основной источник DOM-строк; берёт только незанятые заявки (Executor пуст + «Not started»); дедупликация по хешу строки.
- **Очередь с приоритетами** (`src/shared/engine-core.js`): заявки, появившиеся пачкой, берутся сверху вниз по ранжированному списку типов; выключенные не берутся никогда; неизвестные — по настройке.
- **Клик**: реалистичная последовательность событий (pointerdown→click) по кнопке с тултипом «Start Transaction», распознавание ошибок («уже занято»), случайная задержка 0–40 мс.
- **Лок вкладок**: несколько открытых вкладок `/tasks` не кликают одну заявку дважды (TTL-lock в localStorage).
- **Turbo** (`src/shared/turbo.js`, режим по умолчанию): прямой API-вызов `POST api/FlowDashBoard/InsertTransactions` через мост в MAIN-мир страницы — быстрее клика, включается автоматически для каждой заявки. Тумблера в UI больше нет: Turbo — это не опция, а основной путь захвата. Если Turbo не смог взять заявку (реестр не содержит задачу, сеть, ошибка сервера) — расширение само откатывается на клик по кнопке «Start Transaction» с автоподтверждением диалога, без участия пользователя.

## Настройки попапа

| Параметр | Значение |
|---|---|
| Карточка состояния | крупный статус **БОЕВОЙ** / **DRY RUN** / **ВЫКЛ** + счётчики: взято за сегодня, доля Turbo, среднее время захвата, время последнего |
| Захват включён | мастер-тумблер |
| Порталы | ELD88 / FLOW — компактные переключатели в одну строку, каждый портал независимо |
| Dry Run | логировать вместо кликов |
| Только в активной вкладке | неактивные вкладки не кликают |
| Звук при захвате | короткий сигнал, чтобы не сидеть во вкладке |
| Фильтр журнала | «только захваты и ошибки» — прячет штатные skip'и по типу |
| Приоритеты | вкл/выкл + порядок ↑↓, ручное добавление типов; комбо матчится точным набором чипов («new shift pti» — отдельный пункт) |
| Неизвестные типы | пропускать / брать после известных |
| Задержка, мс | случайный джиттер перед кликом |

Захват всегда пробует Turbo первым и откатывается на клик автоматически — переключать вручную нечего.

## Обновление под платформу

Все селекторы, ключи WS-сообщений и тексты кнопок собраны в одном файле:
`src/shared/platform-config.js`. После редизайна платформы правится только он
(конфиг turbo — секция `turbo` там же).

Результаты инспекции платформы (Фаза 0) фиксируются в `docs/platform-notes.md`.

## Структура

```
manifest.json              MV3, два content script (MAIN + ISOLATED)
src/injected/inject.js     хук WebSocket/SSE + мост для turbo-запросов (main world)
src/content/content.js     наблюдатель DOM, извлечение, клики, локи, журнал
src/shared/engine-core.js  чистая логика: дедуп, фильтры, очередь приоритетов
src/shared/storage.js      конфиг по умолчанию (+ сид-список типов), журнал
src/shared/turbo.js        прямой API-захват (мост MAIN-мир)
src/shared/platform-config.js  ВСЕ селекторы/схемы платформы
src/background/service-worker.js  badge
src/popup/                 UI управления
test/mock.html             тесты engine-core (открыть в браузере)
```

## Известные ограничения

- Если платформа шлёт задачи не через WS, хук бесполезен — работает MutationObserver (не медленнее отрисовки). Уточняется на Фазе 0.
- Fallback-id карточек — хеш контента: две полностью идентичные карточки могут схлопнуться в дедупе.
- Кнопка ищется по тексту/классам-кандидатам; до Фазы 0 возможны ложные срабатывания — потому сначала Dry Run.
