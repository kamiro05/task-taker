Готовые тексты для вкладок Store listing и Privacy в Developer Dashboard.
Копировать как есть; места, требующие вашего решения, помечены `<...>`.

## Пакет

`build/task-taker-<версия>.zip` — собирается из `manifest.json`, `icons/`, `src/`.
Больше в архиве быть ничего не должно: в корне репозитория лежит
`fct-insert-body.json` с настоящими ФИО и номерами прав водителей, и архивация
папки целиком отправила бы эти данные в Google.

```
Task Taker помогает диспетчеру не упускать новые заявки.

Расширение следит за таблицей задач в вашей рабочей панели и, как только
появляется свободная заявка подходящего типа, нажимает «Start Transaction» и
подтверждает диалог — то же самое, что делает человек, только без задержки на
реакцию.

Возможности:

• Приоритеты типов задач. Список задаёте вы: что выше — берётся раньше, снятая
  галочка — не берётся никогда. Если в один момент появилось несколько заявок,
  расширение сначала сравнит их между собой и возьмёт самую важную.
• Фильтр по порталам.
• Dry Run — режим проверки: расширение ведёт журнал, но ничего не берёт.
• Панель на странице задач: состояние захвата, счётчик за смену, включение
  одним кликом. Перетаскивается мышью.
• Горячая клавиша для включения и выключения (назначается в настройках Chrome).
• Мягкий звуковой сигнал при взятии заявки, отключаемый.
• Журнал последних событий и счётчики за сутки.
• Предупреждение, если платформа изменила вёрстку и захват перестал работать —
  иначе поломку замечают только к концу смены.

Расширение работает на одном-единственном сайте, указанном в разрешениях, и
только под вашей учётной записью — никаких дополнительных доступов ему не
требуется. Данные никуда не отправляются: настройки и журнал хранятся в вашем
браузере.
```

**Language:** Russian

## Что скрыть невозможно

Название платформы убрано из имени расширения, описания, попапа и текстов
листинга. Но **домен спрятать нельзя**, и рассчитывать на это не стоит:

- он обязан быть в `host_permissions` и `content_scripts.matches`, иначе
  расширение просто не работает;
- Chrome сам показывает его каждому пользователю при установке и на странице
  расширения: «Чтение и изменение ваших данных на сайте …»;
- он же виден ревьюеру Google и в обосновании разрешений.

Что реально закрывает доступ посторонним:

1. **Visibility: Unlisted или Private.** В поиске магазина расширения не будет,
   ставится по прямой ссылке (Private — ещё и по списку почт).
2. **Приватный репозиторий.** Тогда ссылку на политику придётся дать иначе —
   например, отдельным публичным gist только с текстом `PRIVACY.md`.
3. **Имя репозитория** — `task-taker`, названия платформы в нём нет.
4. `docs/platform-notes.md` — подробный разбор внутренностей платформы:
   селекторы, имена её API, поведение сервера. Для публичного репозитория это
   самый чувствительный файл.

## Privacy

**Единственное назначение** (поле над обоснованиями, 462/1000)

```
Расширение решает одну задачу: помогает диспетчеру быстрее брать свободные рабочие заявки в веб-панели его компании. Расширение следит за таблицей задач на одной странице, и когда там появляется свободная заявка подходящего типа, нажимает кнопку взятия заявки и подтверждает диалог — то же самое действие, которое пользователь до этого выполнял вручную. Пользователь сам задаёт список типов задач и их приоритет. Никакой другой функциональности в расширении нет.
```

**Обоснование (storage)** — 625/1000

```
Разрешение storage используется для хранения пользовательских настроек и локальной статистики. В chrome.storage.local сохраняются: список типов задач с приоритетами, фильтр порталов, задержка перед кликом, состояние переключателей (режим проверки, звук, панель на странице), журнал последних 50 событий работы расширения и счётчики за текущие сутки. В chrome.storage.session хранится список вкладок, в которых пользователь включил захват. Все данные остаются на компьютере пользователя, никуда не передаются и удаляются вместе с расширением. Без этого разрешения настройки сбрасывались бы при каждом открытии окна расширения.
```

**Обоснование (scripting)** — 587/1000

```
Разрешение scripting нужно для кнопки «Подключить движок к этой вкладке» в окне расширения. Chrome не внедряет content scripts во вкладки, открытые до установки или обновления расширения, поэтому пользователю иначе пришлось бы вручную перезагружать рабочую страницу. По нажатию этой кнопки расширение вызывает chrome.scripting.executeScript и внедряет собственные файлы из своего пакета в текущую вкладку. Внедрение возможно только на том единственном домене, который объявлен в манифесте, и только по явному действию пользователя. Удалённый код при этом не загружается и не выполняется.
```

**Обоснование (Разрешение на доступ к хостам)** — 576/1000

```
Расширение работает только на одном сайте — внутренней рабочей панели компании пользователя; её домен указан в host_permissions и content_scripts манифеста. Доступ к этому хосту — основа работы расширения: оно читает строки таблицы задач на странице (тип задачи, статус, портал, занята ли заявка), чтобы найти свободные заявки нужного типа, и нажимает на этой же странице кнопку взятия заявки и кнопку подтверждения в открывшемся диалоге. Никакие другие сайты расширению не доступны. Данные со страницы никуда не передаются и не сохраняются за пределами браузера пользователя.
```

**Если поле обоснования под вопросом об удалённом коде окажется обязательным**

```
Расширение не использует удалённый код. Весь исполняемый код входит в пакет расширения. Внешние скрипты не подключаются, eval() и подобные конструкции не используются.
```

## Инструкции для тестирования

Отдельный пункт в левом меню. Заполнять обязательно: ревьюер не сможет войти в
закрытую корпоративную панель, и без объяснения расширение отклонят с
формулировкой «не удалось проверить работу».

```
Расширение предназначено для сотрудников одной компании и работает только на её внутренней веб-панели, доступ к которой требует корпоративной учётной записи. Публичной демонстрационной версии этой панели не существует, поэтому предоставить тестовый доступ мы не можем.

Что можно проверить без входа в панель:
1. Установите расширение и нажмите на его значок — откроется окно настроек: переключатели, список приоритетов типов задач, журнал и счётчики. Все настройки сохраняются локально.
2. На любой странице, кроме указанного в манифесте домена, расширение не активируется: content script туда не внедряется, никаких элементов на страницу не добавляется.
3. Весь код расширения открыт и не обфусцирован, внешние скрипты не загружаются.

По умолчанию расширение включает режим проверки (Dry Run), в котором оно ничего не нажимает, а только ведёт журнал.
```

**Remote code:** No, I am not using remote code — весь код входит в пакет.

**Data usage:** не отмечать ни одну категорию. Расширение не собирает и не
передаёт данные. Отметить три подтверждения внизу страницы.

**Privacy policy URL**

```
https://github.com/kamiro05/task-taker/blob/master/PRIVACY.md
```

Репозиторий открыт, контактный адрес в `PRIVACY.md` заполнен — ссылка отдаёт
HTTP 200 и готова к вставке в форму. Если репозиторий когда-нибудь снова
станет приватным, ссылка перестанет открываться у ревьюера, и политику придётся
выложить отдельно (например, публичным gist).

## После публикации

1. Удалить распакованную копию расширения из `chrome://extensions`, иначе рядом
   будут работать два экземпляра и оба начнут хватать заявки.
2. Установить расширение по ссылке магазина.
3. Назначить горячую клавишу на `chrome://extensions/shortcuts` — одиночные
   F-клавиши задаются только вручную (см. раздел 37 в platform-notes.md).

Обновление версии: поднять `version` в манифесте → пересобрать zip → загрузить
в консоли → дождаться проверки. Дальше Chrome разносит новую версию всем
пользователям сам, примерно раз в пять часов.
